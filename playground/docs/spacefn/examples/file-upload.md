# File upload to R2

This example accepts one image, checks its size and detected type, stores it
in R2 under a generated key, and returns that key. The browser-provided
filename is never used as an object key.

Declare the bucket in `cloudflare.config.ts`:

```ts
import { defineConfig, bindings } from "cf/config";

export default defineConfig({
	worker: {
		entrypoint: "./app/entry.ts",
		name: "my-app",
		compatibilityDate: "2026-10-19",
		env: {
			UPLOADS: bindings.r2({ name: "my-app-uploads" }),
		},
	},
});
```

## Upload policy

Which files the app accepts is a rule, so it lives in a module. Both the route and the form read it, so the limits cannot drift apart:

```ts
// modules/images/policy.ts

export const IMAGE_TYPES = ["image/png", "image/jpeg"] as const;
export const MAX_IMAGE_BYTES = 5 * 1024 * 1024;

export const imageUploads = {
	maxFileSize: MAX_IMAGE_BYTES,
	maxFiles: 1,
	allowedTypes: [...IMAGE_TYPES],
};
```

## Upload endpoint

Parsing multipart bodies and writing to R2 are HTTP and binding work, so they stay in the route, configured by the policy:

```ts
// app/routes/uploads.ts

import { imageUploads } from "@modules/images/policy";
import { AppError } from "@utils/errors";
import { defineHandler } from "spacefn/handler";
import { putUpload, readUploads } from "spacefn/http";

export const POST = defineHandler(async (c) => {
	const { files } = await readUploads(c, imageUploads);

	const candidate = files.image;
	const file = Array.isArray(candidate) ? candidate[0] : candidate;
	if (!file) throw new AppError("invalid", "Choose an image to upload.", "image_required");

	const key = await putUpload(c.env.UPLOADS as never, file, { prefix: "images" });
	return c.json({ key, size: file.size, type: file.type }, 201);
});
```

`readUploads` enforces the byte limit and, for supported image types, checks
the file signature rather than trusting the browser's `Content-Type` alone.
It throws a status-bearing error for an invalid multipart body, a large file,
or a disallowed type, and `app.onError` returns that status as JSON, as it does
for the route's own `AppError`.

The `as never` adapts Cloudflare's `R2Bucket.put` overload to the helper's
structural bucket type. The key is generated by `putUpload`; callers should
store the returned key with the owning record rather than accept arbitrary
keys from the browser.

## HTML form

Create `app/pages/upload.page.ts`:

```ts
// app/pages/upload.page.ts

import { IMAGE_TYPES, MAX_IMAGE_BYTES } from "@modules/images/policy";
import { definePage, html } from "spacefn/pages";

export default definePage(
	() =>
		html`<main>
			<h1>Upload an image</h1>
			<form method="post" action="/uploads" enctype="multipart/form-data">
				<label>
					Image (PNG or JPEG, up to ${MAX_IMAGE_BYTES / 1024 / 1024} MB)
					<input type="file" name="image" accept=${IMAGE_TYPES.join(",")} required />
				</label>
				<button type="submit">Upload</button>
			</form>
		</main>`,
);
```

The form submits a regular multipart request and navigates to the JSON
response. The `accept` attribute is only a browser hint; the server checks the
file again. For an in-place upload UI, use a browser entry or adapt the
Datastar form pattern after confirming the request uses `multipart/form-data`;
do not send a URL-encoded Datastar form to `readUploads`.

## Serve an authorized object

Do not make an upload public just because its key is hard to guess. Look up
the key from an authorized application record before returning the object.
Whether this user may see this image is a decision, so the module makes it:

```ts
// modules/images/access.ts

import { findImageForOwner } from "@space/db/main_db";
import { AppError } from "@utils/errors";
import type { DbReader } from "spacefn/db";

export async function imageKeyFor(
	db: DbReader,
	user: { id: number } | undefined,
	id: string | undefined,
) {
	if (!user) throw new AppError("unauthorized", "Sign in first.");
	const image = await findImageForOwner(db, { id: Number(id), ownerId: user.id });
	// Someone else's image and a missing one look the same, so ids cannot be probed.
	if (!image) throw new AppError("not_found", "No such image.");
	return image.key;
}
```

The route reads the signed-in user that the [session middleware](../guides/auth.md)
set, asks the module for the key, and streams the object:

```ts
// app/routes/images/[id].ts

import { mainDb } from "@app/db/main_db";
import { imageKeyFor } from "@modules/images/access";
import { defineHandler } from "spacefn/handler";

export const GET = defineHandler(async (c) => {
	const user = c.get("user") as { id: number } | undefined;
	const key = await imageKeyFor(await mainDb(c.env.DB), user, c.req.param("id"));

	const object = await c.env.UPLOADS.get(key);
	if (!object) return c.notFound();

	const headers = new Headers();
	object.writeHttpMetadata(headers);
	headers.set("x-content-type-options", "nosniff");
	return new Response(object.body, { headers });
});
```

`findImageForOwner` is a generated query that matches both the id and the
owner. If the images are intentionally public, create a separate public route
with an explicit policy and cache headers.

See [HTTP helpers](../api-reference/http.md) for parsing and upload options,
and [Cloudflare setup](../guides/cloudflare-v2.md) for bindings.
