# How it works

spacefn is conventions plus codegen. You write files in `app/`; spacefn scans them and writes `.space/`; `app/entry.ts` imports the generated files and wires them into one Worker. This page shows the actual generated code, not just the idea.

## The loop

1. You write code under `app/` (routes, pages, queues, crons, Durable Objects, workflows, database, client entries, env).
2. `space gen` (or the Vite plugin) runs `sync()` and writes `.space/`.
3. `app/entry.ts` imports from `.space/` and becomes the Worker module.
4. Vite serves it in dev; builds it for production.

`modules/`, `utils/` and `lib/` are not scanned. Import them from `app/` files.

## What `.space/` contains

| Generated file              | Comes from                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------ |
| `.space/worker.ts`          | `app/middleware`, `app/queues`, `app/crons`, `app/routes` and `app/pages` (via `./routes`) |
| `.space/routes.ts`          | `app/routes/**`, `app/pages/*.page.ts` and `*.server.ts`, sorted by path specificity       |
| `.space/exports.ts`         | `app/durable-objects`, `app/workflows`                                                     |
| `.space/env.d.ts`           | `app/env.ts`                                                                               |
| `.space/bindings.d.ts`      | `app/env.ts`, `cloudflare.config.ts`, DO/workflow/queue files                              |
| `.space/queues.ts`          | `app/queues/*`                                                                             |
| `.space/client.ts`          | `app/client/*` entries                                                                     |
| `.space/client-manifest.ts` | `app/client/*` (dev URLs; hashed at build)                                                 |
| `.space/db/<name>.ts`       | `app/db/<name>/{migrations,queries,config.ts}`                                             |

Every generated file starts with `// Generated by space. Do not edit.` and is regenerated on every dev start and build. `.space/` is gitignored.

## What the generated code looks like

`.space/routes.ts` mounts routes and pages together, most specific first. Literal paths such as `/hello` register before dynamic paths such as `/:id`:

```ts
// Generated by space. Do not edit.
import { mountPage, mountRoute, type Hono } from "spacefn/runtime";

import page0 from "../app/pages/hello.page";
import * as route1 from "../app/routes/[id]";

export function registerRoutes(app: Hono): void {
	mountPage(app, "/hello", page0, undefined);
	mountRoute(app, "/:id", route1);
}
```

`.space/exports.ts` re-exports Durable Object and Workflow classes so Cloudflare can bind them:

```ts
// Generated by space. Do not edit.
export { Counter } from "../app/durable-objects/counter";
export { OrderFulfillment } from "../app/workflows/order-fulfillment";
```

`.space/bindings.d.ts` types every binding:

```ts
// Generated by space. Do not edit.
import type { DurableObjectNamespace, Workflow } from "@cloudflare/workers-types";

import type { Counter } from "../app/durable-objects/counter";

declare module "spacefn/env" {
	interface CloudflareBindings {
		DO_COUNTER: DurableObjectNamespace<Counter>;
		WF_ORDER_FULFILLMENT: Workflow;
		QUEUE_EMAILS: Queue<unknown>;
	}
}
```

`.space/queues.ts` exposes typed producers:

```ts
// Generated by space. Do not edit.
export const queues = {
	emails: queueProducer<QueueBodyOf<typeof handler0>>("QUEUE_EMAILS"),
} as const;
```

`.space/db/main_db.ts` carries the migrations, a migration runner, and one typed function per query file (see [database](../directory-structure/database.md)).

## How `entry.ts` unifies it

`app/entry.ts` is the one hand-written wiring file:

```ts
// app/entry.ts
import { createApp, registerRoutes, mountApp } from "@space/worker";

import schema from "./env";

const app = createApp({ env: schema });

app.onError((err, c) => c.json({ error: "internal_error", message: "Something went wrong" }, 500));

registerRoutes(app);

export * from "@space/exports";
export default mountApp(app);
```

Line by line:

- `createApp({ env: schema })` builds the Hono app, registers tracing, env validation, and every file in `app/middleware/` in file-name order.
- `app.onError(...)` is your global error handler.
- `registerRoutes(app)` mounts every route and page via `mountRoute` and `mountPage`, sorted by path specificity.
- `export * from "@space/exports"` re-exports Durable Object and Workflow classes at the Worker's top level, so Cloudflare can bind them.
- `export default mountApp(app)` produces the Cloudflare Worker module.

`mountApp` returns three handlers:

- `fetch` — wraps every request: traces the env (`traceBindings`), runs under `AsyncLocalStorage` (`runWithBindings`), then runs the Hono app (`traceConfig`, `traceRequest`, `envMiddleware`, middleware, routes/pages).
- `queue` — routes a queue batch to its consumer (`dispatchQueue`).
- `scheduled` — runs cron jobs whose schedule matches (`dispatchScheduled`).

## Convention folder to generated file to wiring

| Folder                                | Generated file                                               | Wired by                                                             |
| ------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| `app/routes/**`                       | `.space/routes.ts`                                           | `registerRoutes(app)`                                                |
| `app/pages/*.page.ts` + `*.server.ts` | `.space/routes.ts`                                           | `registerRoutes(app)`                                                |
| `app/middleware/*`                    | imported into `.space/worker.ts`                             | `createApp`                                                          |
| `app/env.ts`                          | `.space/env.d.ts`, names in `.space/bindings.d.ts`           | `createApp({ env: schema })`                                         |
| `app/queues/*`                        | `.space/queues.ts`, consumer in `.space/worker.ts`           | `mountApp` → `queue`                                                 |
| `app/crons/*`                         | consumer in `.space/worker.ts`                               | `mountApp` → `scheduled`                                             |
| `app/durable-objects/*`               | `.space/exports.ts`, typed binding in `.space/bindings.d.ts` | `export * from "@space/exports"`                                     |
| `app/workflows/*`                     | `.space/exports.ts`, typed binding in `.space/bindings.d.ts` | `export * from "@space/exports"`                                     |
| `app/db/<name>/...`                   | `.space/db/<name>.ts`                                        | imported directly (`@space/db/<name>`)                               |
| `app/client/*`                        | `.space/client.ts`, `.space/client-manifest.ts`              | imported in pages                                                    |
| `cloudflare.config.ts` (root)         | typed bindings                                               | native Cloudflare config; `entrypoint: "./app/entry.ts"` must be set |

## Generated vs hand-written

- **Hand-written:** everything under `app/`, plus `cloudflare.config.ts`, `vite.config.ts`, and `app/entry.ts`.
- **Generated (never edit, gitignored):** everything under `.space/`. Deterministic: unchanged content is not rewritten.
