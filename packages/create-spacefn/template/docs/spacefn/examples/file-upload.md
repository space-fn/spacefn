# File upload to R2

This example accepts one image, checks its size and detected type, stores it
in R2 under a generated key, and returns that key. The browser-provided
filename is never used as an object key.

Declare the bucket in `cloudflare.config.ts`:

```ts
import { defineConfig, bindings } from "cf/config";

export default defineConfig({
	worker: {
		entrypoint: "./app/entry.ts",
		name: "my-app",
		compatibilityDate: "2026-10-19",
		env: {
			UPLOADS: bindings.r2({ name: "my-app-uploads" }),
		},
	},
});
```

## Upload endpoint

Create `app/routes/uploads.ts`:

```ts
import { defineHandler } from "spacefn/handler";
import { putUpload, readUploads } from "spacefn/http";

export const POST = defineHandler(async (c) => {
	const { files } = await readUploads(c, {
		maxFileSize: 5 * 1024 * 1024,
		maxFiles: 1,
		allowedTypes: ["image/png", "image/jpeg"],
	});

	const candidate = files.image;
	const file = Array.isArray(candidate) ? candidate[0] : candidate;
	if (!file) return c.json({ error: "image_required" }, 400);

	const key = await putUpload(c.env.UPLOADS as never, file, { prefix: "images" });
	return c.json({ key, size: file.size, type: file.type }, 201);
});
```

`readUploads` enforces the byte limit and, for supported image types, checks
the file signature rather than trusting the browser's `Content-Type` alone.
It throws a status-bearing error for an invalid multipart body, a large file,
or a disallowed type; the default handler returns that status as JSON.

The `as never` adapts Cloudflare's `R2Bucket.put` overload to the helper's
structural bucket type. The key is generated by `putUpload`; callers should
store the returned key with the owning record rather than accept arbitrary
keys from the browser.

## HTML form

Create `app/pages/upload.page.ts`:

```ts
import { definePage, html } from "spacefn/pages";

export default definePage(
	() =>
		html`<main>
			<h1>Upload an image</h1>
			<form method="post" action="/uploads" enctype="multipart/form-data">
				<label>
					Image (PNG or JPEG, up to 5 MB)
					<input type="file" name="image" accept="image/png,image/jpeg" required />
				</label>
				<button type="submit">Upload</button>
			</form>
		</main>`,
);
```

The form submits a regular multipart request and navigates to the JSON
response. The `accept` attribute is only a browser hint; the server checks the
file again. For an in-place upload UI, use a browser entry or adapt the
Datastar form pattern after confirming the request uses `multipart/form-data`;
do not send a URL-encoded Datastar form to `readUploads`.

## Serve an authorized object

Do not make an upload public just because its key is hard to guess. Look up
the key from an authorized application record before returning the object:

```ts
// app/routes/images/[id].ts
import { currentUser } from "@modules/auth";
import { findImageForUser } from "@modules/images";
import { defineHandler } from "spacefn/handler";

export const GET = defineHandler(async (c) => {
	const user = currentUser(c);
	const image = await findImageForUser(c.env.DB, {
		id: c.req.param("id"),
		userId: user.id,
	});
	if (!image) return c.notFound();

	const object = await c.env.UPLOADS.get(image.key);
	if (!object) return c.notFound();

	const headers = new Headers();
	object.writeHttpMetadata(headers);
	headers.set("x-content-type-options", "nosniff");
	return new Response(object.body, { headers });
});
```

`findImageForUser` is app-owned: it must verify the caller owns or may access
the record. If the images are intentionally public, create a separate public
route with an explicit policy and cache headers.

See [HTTP helpers](../api-reference/http.md) for parsing and upload options,
and [Cloudflare setup](../guides/cloudflare-v2.md) for bindings.
